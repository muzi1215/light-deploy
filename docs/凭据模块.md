# 凭据模块文档

> 模块包：`com.lx.deploy.credential` ｜ 对应数据表：`credential` ｜ 状态：已完成并编译通过

## 1. 模块定位

凭据模块管理 Git 令牌 / SSH 私钥 / 镜像仓库登录密码等敏感凭据，统一做 AES-GCM 加密存储。它是「凭据密文」的**唯一权威来源**——服务器 SSH 凭据走 `server.ciphertext`，而 Git / 镜像仓库凭据走独立的 `credential` 表。

- 本模块提供：凭据 CRUD、明文提交即加密、密文查询不返回；
- 本模块不提供：SSH 执行（见 [SSH执行层.md](SSH执行层.md)）、凭据明文下发——明文只在建连/登录前短暂解密，用完即弃（AGENTS.md §7）。

## 1.1 调用链路（前端 → 后端）

凭据模块是**纯同步 CRUD**，**不触发 `lds_task`、不连 SSH**。凭据密文在 `CredentialService` 落库前加密；发布时由 `*DeployService` / 构建时由 `BuildTaskHandler` 调 `CredentialCrypto.decrypt` 短暂解密使用（如 `docker login`）。

```text
credential.ts（lighit-deploy-ui/src/api/credential.ts）
  └─ 列表/详情/新增/修改/删除 → GET|POST|PUT|DELETE /credential/*
        ▼
CredentialController                       // credential/controller/CredentialController.java
  （detail@73 / create@86）
        ▼
CredentialService                         // credential/service/CredentialService.java
  → create@126：entity.setEncryptedValue(credentialCrypto.encrypt(...)) @134
  → update@149：encrypt @160
  → delete@177
  → pageByCondition@90（查询响应不含密文）
        ▼
CredentialMapper 直写 credential 表（ciphertext 列存 AES-GCM 密文）
```

消费侧（非本模块，仅说明流向）：

```text
构建时：BuildTaskHandler → GitAuthSupport / RegistryAuthSupport 调 CredentialCrypto.decrypt 取明文
发布时：*DeployService → CredentialCrypto.decrypt 取镜像仓库密码 → docker login
```

## 2. 数据表结构（`credential`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | VARCHAR(32) | 主键 |
| name | VARCHAR(100) | 凭据名称，与 is_deleted 组成唯一键 |
| type | VARCHAR(20) | 凭据类型：`GIT_TOKEN` / `SSH_KEY` / `REGISTRY`（枚举 `CredentialType`） |
| encrypted_value | TEXT | AES-GCM 加密后的密码或私钥，**只写不读** |
| status | TINYINT | 0 停用 / 1 启用（`EnableStatus`） |
| description | VARCHAR(500) | 描述 |

> `encrypted_value` 在实体上标注 `@JsonIgnore`（查询接口不返回）；DTO 无密文字段，属性复制不会把调用方提交内容直接写进 `encrypted_value`，密文只能由本服务 `encrypt` 产生（见 `CredentialService.java:295-296`）。

## 3. 枚举设计

| 枚举 | 取值 | 使用场景 |
| --- | --- | --- |
| `CredentialType` | GIT_TOKEN / SSH_KEY / REGISTRY | 凭据类型；`project.git_credential_id` 限定 GIT_TOKEN/SSH_KEY，`registry.credential_id` 限定 REGISTRY |

状态用 `TINYINT` + `EnableStatus` 常量（AGENTS.md §4.5）。

## 5. 接口清单

| 方法 | 路径 | 说明 | 关键方法@行 |
| --- | --- | --- | --- |
| GET | `/credential/page` `/credential/list` | 分页/列表（不含密文） | `CredentialService.pageByCondition@90` |
| GET | `/credential/detail/{id}` | 详情（不含密文） | `CredentialController.detail@73` |

## 6. 核心业务规则

- **明文不落库**：`create`/`update` 收到明文凭据后 `CredentialCrypto.encrypt` 加密再存；密文列 `@JsonIgnore`，任何响应都不含明文（AGENTS.md §7）。
- **引用保护**：被 `project.git_credential_id` 或 `registry.credential_id` 引用期间不允许删除（由 `ProjectService`/`RegistryService` 在删除前校验）。
- **类型与引用必须匹配**：项目只接受 GIT_TOKEN/SSH_KEY；仓库只接受 REGISTRY（见 [项目模块.md §6.6](项目模块.md) / [镜像仓库模块.md §6.2](镜像仓库模块.md)）。
- **AES key 只走环境变量**：`LIGHT_DEPLOY_AES_KEY` 注入，绝不提交 Git、不写源码（AGENTS.md §7）。

## 7. 与其他模块的关系

| 方向 | 关系 |
| --- | --- |
| → project / registry 模块 | 凭据被引用；删除前反向拦截 |
| → build / deployment 模块 | 构建/发布时由 `CredentialCrypto.decrypt` 短暂解密用于 Git 克隆、`docker login` |
| → ssh / 服务器模块 | 服务器 SSH 凭据走 `server.ciphertext`（同套加解密，但不存本表） |

## 8. 已知边界与后续演进

- **密文先加密后比较**：不支持「凭据内容查重」，同名凭据靠 `name` 唯一键区分；
- **密钥丢失即全量失效**：`LIGHT_DEPLOY_AES_KEY` 变更会使所有存量密文无法解密，迁移需谨慎；
- **私钥只支持未加密 OpenSSH/PKCS#8**：带口令的私钥会提示而非静默失败。
