# 服务器模块文档

> 模块包：`com.lx.deploy.server` ｜ 对应数据表：`server` ｜ 状态：已完成并编译通过

## 1. 模块定位

服务器模块管理被纳管的目标服务器与构建机的 **SSH 连接档案**：`host / ssh_port / username / auth_type / ciphertext(密文) / environment_tag / status`，以及三处目录（部署根目录、构建工作区、产物持久目录）。它是所有 SSH/SFTP 操作的**连接来源**——发布连目标机、构建连构建机，都从这里取档案。

- 本模块提供：服务器档案 CRUD、连通性测试（`SERVER_TEST` 异步任务）、凭据密文只写不读；
- 本模块不提供：具体发布 / 构建动作（由 deployment / build 模块消费其连接配置）、凭据明文（引用 `credential` 表，密文 AES-GCM 加解密见 [凭据模块.md](凭据模块.md)）。

## 1.1 调用链路（前端 → 后端 → 执行器）

服务器档案本身是同步 CRUD；唯一异步入口是「连通性测试」。注意它**不直连**执行器——只插一条 `lds_task`（task_type=SERVER_TEST、status=0）就返回，由 `TaskExecutor` 轮询触发 `ServerTestTaskHandler`（详见 [讲解文档.md](讲解文档.md)）。

```text
server.ts: testServerConnectivity(id)         // 前端 api 函数（lighit-deploy-ui/src/api/server.ts:53）
        │  POST /server/test/{id}
        ▼
ServerController.test()                       // server/controller/ServerController.java:136
        ▼
ServerService.submitConnectivityTest(id)      // server/service/ServerService.java:76
        │  hasUnfinishedTask 防重 → taskService.create(dto) 插 SERVER_TEST 任务（task_type=SERVER_TEST）
        ▼  （立即返回 taskId）
┄┄┄┄┄┄┄┄┄┄┄┄ TaskExecutor 轮询 ┄┄┄┄┄┄┄┄┄┄┄┄
ServerTestTaskHandler.execute(task)           // task/executor/ServerTestTaskHandler.java:164
        │  SshSessionFactory.open(server) 解密凭据建连 → 只读探活（uname/java/git/docker/df/部署目录）
        ▼
lds_task_log（前端 GET /taskLog/pull 增量拉取）
```

同步 CRUD 链路统一为：`server.ts` 的列表/详情/新增/修改/删除 → `GET|POST|PUT|DELETE /server/*` → `ServerController`（detail@87 / create@101）→ `ServerService` → `ServerMapper` 直写 `server` 表，**不触发任务、不连 SSH**。

## 2. 数据表结构（`server`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | VARCHAR(32) | 主键，MyBatis-Plus `ASSIGN_UUID` |
| server_name / host | VARCHAR | 名称、地址 |
| ssh_port | INT | SSH 端口，默认 22 |
| username | VARCHAR | SSH 登录用户 |
| auth_type | TINYINT | 1 密码 / 2 私钥（枚举 `ServerAuthType`） |
| ciphertext | TEXT | AES-GCM 加密后的密码或私钥，**只写不读**（`@JsonIgnore`，查询接口不返回） |
| environment_tag | TINYINT | 环境标签（枚举 `EnvironmentTag`：1 开发 / 2 测试 / 3 生产），**仅用于列表筛选与着色，不参与发布决策**（见 [环境与部署目标.md §4](环境与部署目标.md)） |
| agent_base_dir | VARCHAR | 部署根目录（目标机），JAR/STATIC 工作目录回落基准 |
| build_workspace_dir | VARCHAR | 构建工作区（构建机），默认 `/opt/light-deploy/build-workspace` |
| build_artifact_dir | VARCHAR | 产物持久目录（构建机），默认 `/opt/light-deploy/artifacts`；更换后历史 `release_record.artifact_path` 会失效 |
| status | TINYINT | 0 停用 / 1 启用（常量 `EnableStatus`） |

> `ciphertext` 在实体上标注 `@JsonProperty(access = WRITE_ONLY)` + `@Schema(accessMode = WRITE_ONLY)`：新增/修改提交明文，Service 写入前 `CredentialCrypto.encrypt` 加密；任何查询响应都不含密文。

## 3. 枚举设计

| 常量/枚举 | 取值 |
| --- | --- |
| `ServerAuthType`（枚举） | 1 密码 / 2 私钥 |
| `EnvironmentTag`（枚举） | 1 开发 / 2 测试 / 3 生产（仅展示，不参与发布） |
| `EnableStatus`（常量） | 0 停用 / 1 启用 |

状态类字段用 `TINYINT` + 常量类，禁止枚举表达状态（AGENTS.md §4.5）。

| 方法 | 路径 | 说明 | 关键方法@行 |
| --- | --- | --- | --- |

## 6. 核心业务规则

- **密文只写不读**：`ciphertext` 字段 `@JsonIgnore`，查询接口（`ServerVo`）永不返回；写入由 `CredentialCrypto.encrypt` 在 Service 层完成，日志/响应不出现明文（AGENTS.md §7）。
- **连通性测试防重**：`submitConnectivityTest` 先 `taskService.hasUnfinishedTask(SERVER_TEST, id)`，已有进行中任务则拒绝。
- **删除顺序**：服务器被部署目标引用时，应先停用/解绑目标再删服务器（反向保护未实现，见 §8）。
- **`environment_tag` 是展示字段**：与 `environment` 表无外键无校验；把它设成「生产」不会让该机器自动成为生产发布目标，真正决定发哪台的是 `project_environment_target`（见 [环境与部署目标.md](环境与部署目标.md)）。

## 7. 与其他模块的关系

| 方向 | 关系 |
| --- | --- |
| → deployment / build 模块 | 目标机/构建机连接配置来源；`SshSessionFactory.open(server)` 解密建连 |
| → 凭据模块 | `auth_type` + `ciphertext` 的加解密由 `CredentialCrypto` 收口 |
| → task 模块 | `POST /server/test/{id}` 提交 `SERVER_TEST` 任务，日志走 `/taskLog/pull` |
| ← 前端 | 服务器管理页（系统设置 → 服务器）；「连通性测试」按钮打开日志抽屉 |

## 8. 已知边界与后续演进

- **删除无反向保护**：删服务器不会阻止「部署目标仍引用它」；应规范操作顺序「先删部署目标 → 再删服务器」；
- **`environment_tag` 不参与发布**：纯展示，运维易误用，已多次强调（见 [环境与部署目标.md](环境与部署目标.md)）；
- **SSH 主机密钥未校验**：`SshClient` 未设 `ServerKeyVerifier`，生产启用前需补齐（见 [SSH执行层.md](SSH执行层.md)）。
