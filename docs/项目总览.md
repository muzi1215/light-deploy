# Light Deploy 项目总览

> 版本基线：2026-09-02 ｜ 文档状态：与代码当前进度一致，每个模块交付后更新

## 1. 项目定位

Light Deploy 是面向中小企业的轻量化部署发布平台。采用 Spring Boot 单体架构，通过 SSH/SFTP 管理多台 Linux 目标服务器，支持 DOCKER / JAR / STATIC 三种运行时的构建与发布。

- 规模基线：至少纳管 6 台服务器，支持不同服务器上的项目并发发布；
- 同一台服务器同一时刻默认只执行一个发布任务；
- 与已上线的 AIops 系统联动：发布期间自动开告警静默窗口，发布稳定后关闭，并提供发布风险建议；
- 平台自身以 Docker 作为主要交付方式。

### 已完成模块要点

**服务器模块**：SSH 凭据 AES-GCM 加密落库（ciphertext 只写不读）、认证类型/环境标签/状态三枚举、标准六接口、软删除。

**项目模块**：项目→环境→目标服务器三层发布拓扑；「一个 project = 一个可部署的服务模块」建模，多模块仓库靠 `build_config_json.module_name` 区分；RuntimeType / SourceType / BuildMode / DeployStrategy 四枚举 + `EnableStatus` 状态常量；编码唯一性、GIT 来源强制 gitUrl、三段 JSON 配置格式校验（键名 schema 见 [项目模块.md §2.3](项目模块.md)）、删除引用保护、主目标互斥（事务内自动降级旧主目标）、跨模块校验注入对方 Mapper 避免循环依赖。

**状态编码改造（2026-09-23）**：全库状态 / 结果字段由字符串编码改为 `TINYINT` 数字编码，Java 侧不再使用状态枚举，统一改为 `com.lx.deploy.common.constants` 下的常量类（`EnableStatus`、`TaskStatus`）；实体 / DTO / VO 的状态字段类型统一 `Integer`，前端状态字段同步改为 `number`。规则见 AGENTS.md §4.5、§22.4。

已有数据库必须手工执行迁移（`schema.sql` 只对全新环境生效，应用启动不会自动执行脚本）：

```bash
# 1. 改造（幂等，可重复执行；需要 CREATE ROUTINE 权限，root 即可）
mysql -h127.0.0.1 -uroot -p deploy < src/main/resources/db/upgrade-status-to-numeric.sql

# 2. server.ciphertext 扩宽为 TEXT（幂等；早期建库是 VARCHAR(130)，私钥密文会被拒绝或截断）
mysql -h127.0.0.1 -uroot -p deploy < src/main/resources/db/upgrade-server-ciphertext-to-text.sql

# 3. 基础时间列收敛为 DATETIME（幂等；早期建库是 TIMESTAMP，会随会话时区隐式换算且存在 2038 上限）
mysql -h127.0.0.1 -uroot -p deploy < src/main/resources/db/upgrade-base-time-to-datetime.sql

# 4. project.registry_id（幂等；镜像仓库绑定列，早期建库缺失）
mysql -h127.0.0.1 -uroot -p deploy < src/main/resources/db/upgrade-project-registry-id.sql

# 5. 校验（只读）：逐列输出实际类型 / 注释 / 索引 / 时间列与期望值的比对结论
mysql -h127.0.0.1 -uroot -p deploy < src/main/resources/db/verify-schema-columns.sql
```

另外两张新表（`credential`、`registry`）已在 `schema.sql` 中定义，早期建库的库需要单独执行这两段 DDL（`CREATE TABLE IF NOT EXISTS`，可重复执行）。

校验结果里凡是出现「需要迁移」「索引缺失」「索引列不匹配」，都说明对应表还没改到位；「表不存在」属于该模块尚未建表，可忽略。

**update_time 不刷新问题（2026-09-23 修复）**：现象是「接口更新成功、数据确实改了，但 `update_time` 停在上一次修改时间」。根因在 `MybatisPlusConfig` 的自动填充器：`strictUpdateFill` 只在字段为 `null` 时才填充，而修改类 Service 是「先查出实体 → 覆盖 DTO 字段 → `updateById`」，实体上的 `updateTime` 已是库里的旧值（非 null），于是被跳过填充、旧值被显式写进 `SET` 子句，MySQL 的 `ON UPDATE CURRENT_TIMESTAMP` 因「列被显式赋值」而不再生效。修复为无条件覆盖 `updateTime`，并已通过 `/project`、`/environment`、`/projectEnvironmentTarget`、`/server` 四个真实更新接口逐个验证时间前进（`server` 不传凭据更新时原有密文保持不丢）。同一轮排查中确认并收敛了两处库表漂移：`project.status` 由 `int` 收敛为 `tinyint`、全库 `create_time` / `update_time` 由 `TIMESTAMP` 收敛为 `DATETIME`。规则见 AGENTS.md §4.3、§10.2。

**凭据 + 镜像仓库模块（2026-09-23）**：凭据保存 Git 令牌 / 私钥与镜像仓库登录密码，明文只写不读（DTO 只有明文入参、VO 不声明密文字段、密文只由 Service 的 encrypt 产生），删除前检查项目与仓库的引用；镜像仓库登记镜像推送目标（地址 / 命名空间 / 凭据 / 启用状态），**只服务于 DOCKER 运行时**。同一轮落地了两条组合约束：`runtime_type` × `build_mode` 的允许矩阵（规则唯一来源是 `RuntimeType.supportedBuildModes`）与 `registry_id` 的 DOCKER 专属绑定；并把 `project` 的可清空字段（`git_url` / `git_branch` / `git_credential_id` / `registry_id` / `description`）补上 `FieldStrategy.ALWAYS`，修掉「切到非 DOCKER 运行时后镜像仓库绑定残留」的问题。规则见 AGENTS.md §10.1、§23.4。

**任务模块 + SSH 执行层（2026-09-23）**：这是第一个「页面点一下、真实连上目标机、日志滚起来」的端到端功能。执行器按「轮询 `lds_task` + 原子抢占（`markRunning` 带状态条件更新）+ 并发令牌（`light-deploy.task.pool-size`，默认 6）+ 互斥键（同一服务器同时只跑一个任务）」调度，启动时把进程重启残留的执行中任务收敛为失败；处理器通过 `TaskHandler` SPI 注册（SERVER_TEST 已实现，BUILD / DEPLOY 按同样方式接入）。`SshSessionFactory` 是密码/私钥两种认证的唯一解密点，命令非零退出码不抛异常、输出经 `maskSecrets` 脱敏。前端用「右侧抽屉 + 增量拉取 `GET /taskLog/pull?taskId=&lastSeq=`」滚动日志，禁止分页轮询。规则见 AGENTS.md §24、§20.9。

**前端工程**：Vue3 管理端（lighit-deploy-ui），假登录 + 二级静态菜单；服务器/项目/环境/部署目标/任务列表五个管理页对接后端接口，表单校验与后端规则镜像，搜索框支持回车查询；vite 代理 /api → 2027/deploy，typecheck 与生产构建均通过。

## 7. 关键开发约定（摘要）

完整约定见项目根目录 `agents.md`，此处仅列高频项：

- 纯 CRUD 不建 Service 接口，`XxxService extends ServiceImpl`；
- Controller 只做参数接收/校验/调用 Service/包装响应，请求 DTO、响应 VO，不暴露实体；
- 主键统一 `IdGenerator.generateUUID()`，禁止 `UUID.randomUUID()`；
- 业务枚举统一放 `com.lx.deploy.common.enums.{module}`，业务包不再各自维护 `enums` 子包（AGENTS.md §22）；
- 状态 / 结果类字段一律 `TINYINT` 数字编码 + `common.constants` 常量类，禁止用字符串编码或枚举表达状态（AGENTS.md §4.5、§22.4）；
- 实时日志一律用 `GET /taskLog/pull?taskId=&lastSeq=` 增量拉取（锚点是 `sequence_no`，不是主键 id），禁止用分页接口轮询；停止条件是「`finished === true` 且本批条数 `< limit`」（AGENTS.md §20.9）；
- 远程执行统一走 `com.lx.deploy.ssh`：凭据只在建连前解密、命令非零退出码不抛异常、输出必须脱敏（AGENTS.md §24.3）；
- 前端列表页与搜索表单统一复制 `views/server/index.vue` 骨架：表格列全部居中、创建时间列宽 200、操作列宽 260、搜索框宽度 180/160（AGENTS.md §20.8）；
- 删除一律软删除，唯一冲突抛 `DATA_CONFLICT(4005)`；
- 凭据只在执行前短暂解密，日志/响应/数据库不出现明文；
- 数据库脚本手工执行，`spring.sql.init.mode` 保持 `never`；
- 每模块交付必须同步中文模块文档（AGENTS.md §13.2）并完成模型层字段注释精化（AGENTS.md §13.1），本文档进度表同步更新；
- Java 代码或模板修改后至少执行 `mvn -o -q -DskipTests compile` 验证。

## 8. 最终效果预期

一台平台服务器（单容器）纳管 6+ 台目标机。运维在页面上完成：登记服务器（凭据加密落库）→ 建项目（选运行时与构建模式）→ 绑定项目到环境的目标机器 → 选版本一键发布。发布过程日志按阶段实时滚动，AIops 静默窗口自动开启；健康检查通过才标记成功，失败按策略停止后续批次，支持回滚到任意保留版本（retain_release_count 控制保留数）。全程无需人工 SSH 登录目标机。

一句话定位：**把手工 SSH 部署脚本，变成一个团队都能安全使用的平台。**
