# 项目总览（Light Deploy）

> 轻量化部署发布平台：Spring Boot 单体 + SSH/SFTP 管理多台 Linux 服务器，面向中小企业的「构建 → 发布 → 回滚 → 告警联动」一体化链路。
> 当前状态：后端核心链路已完成并编译通过，端到端真机验证部分完成。

---

## 1. 全局架构与「请求—执行分离」

本平台所有长任务（构建 / 发布 / 回滚 / 连通性测试）都遵循同一套**解耦模型**：

```text
前端 → Controller（只插一条 lds_task 排队记录 + 业务主记录，立即返回）
        │
        │  （HTTP 请求在此结束，链路"断开"）
        ▼
后台 TaskExecutor（独立线程，每 1 秒轮询 lds_task）
        │  markRunning 原子抢占 → 提交 worker 线程池
        ▼
Handler.execute(task)   ← 真正 SSH 连服务器干活的代码
        │
        ▼
前端轮询 GET /taskLog/pull 看实时日志
```

**为什么这么设计、以及 `DeployTaskHandler` 这种类"找不到被谁调用"怎么办，见 [讲解文档.md](讲解文档.md)。**
该文档是全平台的「调用链路总入口」，含精确到行号的 `前端api → Controller.方法 → Service.方法 → Handler.方法 → 实际动作` 总地图。

---

## 2. 一条纵向主链路

```text
构建模块（代码 → 可发布版本 release_record）
        │  BuildController.create → BuildService.createAndTrigger → BuildTaskHandler（连构建机）
        ▼
发布模块（版本 + 项目拓扑 → 目标机运行实例）
        │  DeploymentController.create → DeploymentService.createAndTrigger → DeployTaskHandler（连目标机）
        ▼
AIops 联动（发布期间告警静默窗 + 风险事件）
        │  发布线程内同步 HTTP 调 AiopsClient（RestClient）
        ▼
SSH 执行层（SshSession：ChannelExec / SftpClient，连构建机与目标机）
```

横向支撑模块：服务器（资产 + SSH 凭据）、项目（运行时/构建模式/拓扑）、环境与部署目标（发布拓扑）、
凭据（加解密）、镜像仓库（Docker 推送目标）、操作日志（`@OperLog` 切面）、任务（调度中枢 + 日志）。

## 4. 后续路线

1. **端到端真机验证**：构建 / 发布 / 回滚三条运行时链路在真实机器上跑通并固化操作手册；
2. **发布防重与并发发布的细粒度**：当前 `ALL_AT_ONCE` 批次内仍串行，全量并发发布待做；
3. **多实例部署**：`TaskExecutor` 当前按单实例轮询设计，多实例需改 Redis 队列或分布式锁；
4. **统一权限中心**：`user` 表仅过渡期联调用，后续接入统一权限中心，业务表只留外部用户 ID；
5. **AIops 风险建议闭环**：v1 已接通静默窗与事件上报，风险建议（回滚建议等）待 AIops 侧深化。

## 5. 阅读建议

第一次接手代码，按这个顺序读：

1. [讲解文档.md](讲解文档.md) —— 先建立「请求与执行分离」的心智模型，否则会在 Handler 里迷路；
2. [任务模块.md](任务模块.md) —— 理解 `TaskExecutor` 这个发动机；
3. 再按你负责的模块读对应的 `Xxx模块.md` 的「调用链路」节；
4. 顺着 `Controller → Service → Handler` 读源码，必要时用 `GET /taskLog/pull` 的链路反查。
