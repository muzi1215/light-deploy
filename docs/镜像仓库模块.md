# 镜像仓库模块文档

> 模块包：`com.lx.deploy.registry` ｜ 对应数据表：`registry` ｜ 状态：已完成，真机验证通过（含引用保护）

## 1. 模块定位

镜像仓库模块登记 **Docker 镜像的推送目标**：私有 Harbor、阿里云 ACR、Docker Hub 等，以及登录该仓库所用的凭据。

- 本模块提供：仓库档案（地址 / 命名空间 / 登录凭据 / 启用状态）、名称唯一性、凭据引用校验、删除前的引用保护；
- 本模块不提供：镜像的构建与推送动作（由后续构建模块执行）、凭据内容（引用 `credential` 表）；
- **只服务于 DOCKER 运行时**：脚本部署（SCRIPT_DEPLOY）与仅发布产物（ARTIFACT_ONLY）产出 JAR / 静态产物 / 部署脚本，不产出镜像，也就不需要仓库（AGENTS.md §23.4）。所以「项目绑定仓库」的入口只在运行时为 Docker 时出现，且不是必填。

## 2. 数据表结构（`registry`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | VARCHAR(32) | 主键，MyBatis-Plus `ASSIGN_UUID` 生成 |
| name | VARCHAR(100) | 仓库名称，必填，与 is_deleted 组成唯一键 |
| registry_url | VARCHAR(255) | 仓库地址，必填，不带 `https://` 前缀 |
| namespace | VARCHAR(150) | 命名空间 / 租户，选填 |
| credential_id | VARCHAR(32) | 登录凭据 ID，引用 `credential` 表；公共仓库留空 |
| status | TINYINT | 仓库状态：0 停用，1 启用（数字编码，Java 侧 `Integer`） |
| description | VARCHAR(500) | 仓库描述 |
| create_time / update_time / is_deleted | - | BaseEntity 统一审计字段，软删除 |

唯一键：`uk_registry_name (name, is_deleted)`。

## 3. 枚举设计

本模块**没有专用枚举**：

- 仓库状态用 `status` 数字编码 + `EnableStatus` 常量（0 停用 / 1 启用），与 project / server 状态同口径（AGENTS.md §22.4）；
- 日志层面的「仓库类型」（Harbor / ACR / Docker Hub）当前没有区分，因为推送命令只依赖地址与凭据。

## 5. 接口清单

统一前缀 `/registry`，统一返回 `ApiResponse<T>` 并携带 `requestId`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/registry/page` | 条件分页查询（name / registryUrl / credentialId / status） |
| GET | `/registry/list` | 条件列表查询；`?status=1` 只返回启用中的仓库（项目表单下拉用） |
| GET | `/registry/{id}` | 主键查询，不存在抛 DATA_NOT_FOUND(4004) |
| POST | `/registry` | 新增，name / registryUrl 必填 |
| PUT | `/registry/{id}` | 修改 |
| DELETE | `/registry/{id}` | 逻辑删除，被项目绑定时拒绝 |

## 6. 核心业务规则与代码逻辑

### 6.1 校验规则（与前端表单镜像）

| 规则 | 不满足时的响应 |
| --- | --- |
| 名称必填、长度 ≤ 100、不重复 | VALIDATION_ERROR(4001) / DATA_CONFLICT(4005) |
| 地址必填、长度 ≤ 255 | VALIDATION_ERROR(4001) |
| 状态必须是 0 或 1 | VALIDATION_ERROR(4001) |
| `credentialId` 填写时必须存在 | VALIDATION_ERROR(4001)「绑定的凭据不存在，请重新选择」 |
| `credentialId` 类型必须是 REGISTRY | VALIDATION_ERROR(4001)「镜像仓库只能绑定类型为 REGISTRY 的凭据」 |

新增时未指定 `status` 由 `applyDefaultValue()` 显式填充为启用，不依赖数据库 DEFAULT —— 保证新增接口返回的 VO 与库内数据一致。

### 6.2 凭据引用校验

```java
Credential credential = credentialMapper.selectById(credentialId);
if (credential == null) { throw ... "绑定的凭据不存在，请重新选择"; }
if (CredentialType.fromCode(credential.getType()) != CredentialType.REGISTRY) { throw ... }
```

两件事必须同时成立：凭据存在（否则推送时解密失败）、类型是 REGISTRY（Git 令牌不能登录镜像仓库）。
公共仓库（Docker Hub）可以不填凭据。

### 6.3 引用保护（删除前检查）

`Project.registryId` 引用本表：删除前统计 `project.registry_id = #{id}` 的项目数量，
大于 0 抛 `DATA_CONFLICT(4005)`「镜像仓库仍被 N 个项目绑定，请先解除项目的仓库绑定」。

### 6.4 查询规则

- `name` / `registryUrl` / `credentialId` / `status` 参与等值查询；
- `namespace` 与 `description` **不参与查询**（自由文本，等值过滤没有业务价值）；
- 列表按 `create_time` 倒序。

## 7. 与其他模块的关系

| 方向 | 关系 |
| --- | --- |
| ← project 模块 | `project.registry_id` 引用本表；ProjectService 校验仓库存在、启用，且只有 DOCKER 运行时可绑定 |
| → credential 模块 | `credential_id` 引用凭据表，类型必须是 REGISTRY |
| → 后续构建模块 | 分层构建（LAYERED_DOCKER）推 base 与 app 镜像时读取本表的地址、命名空间与凭据 |
| ← 前端 | 系统设置 → 镜像仓库页面；项目表单在运行时为 Docker 时出现「镜像仓库」下拉（取 `?status=1`） |

## 8. 已知边界与后续演进

- **仓库类型未建模**：Harbor 与 ACR 的推送协议不同（`docker push` 即可满足当前范围），若将来需要调用厂商 API（如清理旧镜像）再补类型字段；
- **不校验地址可达性**：新增仓库时不做登录测试（类似服务器连通性测试的能力尚未提供），配置错误要到首次推送才暴露；
- **不保存镜像清单**：哪些镜像已经推到这个仓库由构建产物表 `build_artifact` 记录，本表只描述「推到哪儿」；
- **删除保护只覆盖项目绑定**：`build_artifact` 里登记过的历史推送不在保护范围内（历史产物不阻碍仓库下线）；
- 停用的仓库不允许被新项目绑定，但**已绑定项目不受影响**：停用只是阻止新增绑定，不会自动解绑，需要人工解除。
