# 前端工程文档

> 工程目录：`lighit-deploy-ui`（与后端同仓库） ｜ 技术栈：Vue3 + Vite + TypeScript + Element Plus + Pinia ｜ 状态：已完成并构建通过

## 1. 模块定位

前端工程是 Light Deploy 平台的操作入口，当前完成第一版管理页面：

- 过渡期假登录（前端 mock，不依赖后端登录接口）；
- 静态菜单（不依赖后端菜单 JSON）；
- 服务器 / 项目 / 环境 / 部署目标 / 任务 / 凭据 / 镜像仓库七个管理页面，对接后端已完成的标准六接口；服务器列表已提供连通性测试入口与实时日志抽屉；
- 生产环境由 Nginx 托管 `dist/` 静态文件并反向代理后端（未配置，待部署阶段）。

## 3. 关键适配点

### 3.1 代理链路

```text
浏览器 → http://localhost:9850/api/xxx
       → vite proxy 重写 /api → /deploy
       → http://localhost:2027/deploy/xxx（Spring Boot，context-path=/deploy）
```

### 3.2 响应契约

`utils/request.ts` 判定 `code === 200` 为成功（与后端 `ResponseCode.SUCCESS` 一致），业务码非 200（如 4001 参数错误、4004 数据不存在、4005 唯一冲突）时以 `ElMessage` 弹出后端 message 并 reject —— 页面无需重复处理错误提示。requestId 已在响应中返回，反馈问题时可直接提供。

### 3.3 假登录与静态菜单

- `api/user.ts` 的 login/getInfo/logout 均为前端 mock，任意用户名密码可登录，token 为 `mock_token_时间戳` 存 Cookie；
- `getInfo` 返回 `routers: []`，`permission.ts` 据此走静态路由模式；
- 四个业务页面注册在 `router/index.ts` 的 `constantRoutes` 中；
- 对接真实登录时，只需按 `api/user.ts` 底部注释切换为真实 API 调用。

## 4. 页面与业务规则映射

菜单为二级结构：一级是分组目录（`alwaysShow: true` + 图标），页面挂二级（完整约定见 AGENTS.md §20.1）：

| 一级目录 | 二级页面 | 路由 | 关键业务规则（与后端一致） |
| --- | --- | --- | --- |
| 服务器管理 | 服务器列表 | /server/list | 新增凭据必填、编辑留空保留旧凭据（密文永不回显）；环境标签颜色走 `constants/tagStyle.ts`，开发 primary / 测试 info / 生产 success；操作列「连通性测试」按钮调用 `POST /server/{id}/test` 创建任务后打开日志抽屉，`setInterval` 1.5s 调 `GET /taskLog/pull?taskId=&lastSeq=` 增量追加日志，任务进入终态即停止轮询 |
| 项目管理 | 项目列表 | /project/list | 检索支持「运行时 + 构建模式」两个下拉（构建模式取值只维护在 `BUILD_MODE_OPTIONS`，搜索下拉/表单下拉/列表映射同一份来源）；编码格式 2-64 位校验；GIT 来源联动显示并强制 gitUrl、可填凭据 ID；保留版本数 1-100；三段 JSON 配置（构建/运行/健康检查）提供原始文本编辑入口，前端只做 JSON 语法校验（键名 schema 见 [项目模块.md §2.3](项目模块.md)）；同一 Git 地址+分支允许建多个项目（一个 project = 一个可部署服务模块）；构建模式下拉随运行时联动（Docker 类模式只配 DOCKER，脚本/仅发布产物只配 JAR 与 STATIC），「镜像仓库」下拉只在运行时为 Docker 时出现（AGENTS.md §23.4）；「Git 凭据」下拉只列 GIT_TOKEN / SSH_KEY 凭据 |
| 项目管理 | 环境管理 | /project/environment | 编码小写格式校验；默认服务器下拉取启用服务器；AIops 开关 |
| 项目管理 | 部署目标 | /project/deploy-target | 项目/环境/服务器三级下拉（服务器仅启用项）；主目标互斥提示；列表本地名称映射 |
| 任务管理 | 任务列表 | /task/list | 状态/阶段/日志级别映射统一复用 `constants/taskStatus.ts`；终态任务不可删除前提示；执行日志控制台与连通性测试抽屉共用同一套全局样式与增量拉取逻辑 |
| 系统设置 | 凭据管理 | /system/credential | 明文凭据只写不读：新增必填、编辑留空表示保留原凭据；列表不展示任何凭据内容；被项目或镜像仓库引用时删除返回 4005；类型下拉与标签走 `constants/credentialType.ts` |
| 系统设置 | 镜像仓库 | /system/registry | 名称/地址必填、状态数字编码；登录凭据下拉只列类型为 REGISTRY 的凭据（与后端校验一致）；被项目绑定时删除返回 4005；列表「登录凭据」列把 credentialId 映射为凭据名称 |

对话框表单统一布局（完整骨架与规则见 AGENTS.md §20.2）：宽度 800px、label-width 120px、size="small"；表单外层包滚动容器 `style="max-height: 60vh; overflow-y: auto; padding: 16px 18px 0 10px;"`，`padding-top: 16px` 保证首行字段与标题栏留出间隔，左右 padding 抵消 `el-row :gutter` 负边距并预留滚动条宽度，页脚按钮始终可见；字段用 `el-row :gutter="20"` 两列排布（普通字段 `:span="12"`、文本域 `:span="24"`），控件宽度统一 `style="width: 100%"`；只读展示字段用 disabled 输入框配枚举文本映射；页脚统一 `#footer` 插槽的"取 消 / 确 定"小按钮；文本域（凭据/描述等）一律放表单最底部。

表单校验规则与后端 Service 校验保持镜像（编码正则、必填项、下限值），前端先拦一遍，后端为准。

列表页与搜索表单统一以 `views/server/index.vue` 为基准骨架（完整规则见 AGENTS.md §20.8）：搜索区文本输入框宽 `180px`、下拉宽 `160px` 且文本输入框绑定回车查询；表格 `border stripe`，所有列显式 `align="center"` 且**一律使用 `min-width`、禁止固定 `width`**，创建时间列 `min-width="200"`、描述列 `min-width="150"` 且排在创建时间之前，操作列 `min-width="260"` 固定右侧；分页 `page-sizes` 为 `[10, 20, 50, 100]`，右对齐。新增列表页直接复制该骨架，不再各自设计布局。

复杂配置字段（三段 JSON 等）在表单 label 后加「?」图标 + `el-tooltip` 展示完整示例，示例常量与输入框 `placeholder` 共用一份；`.form-tip`、`.form-label-tip`、`.tooltip-json` 统一定义在全局 `styles/index.scss`（AGENTS.md §20.2）。

实时日志（连通性测试、任务详情）统一使用「右侧 `el-drawer` + 终端风格控制台」：抽屉宽度 800px，日志区自动滚到底部，任务状态/进度/阶段/失败原因同屏展示（失败原因用 `el-alert`），刷新一律走 `GET /taskLog/pull` 增量拉取（完整规则见 AGENTS.md §20.9）。控制台样式只在全局 `styles/index.scss` 定义一份，页面禁止再写 scoped 样式。

状态类字段全部使用数字编码：前端类型为 `number`，下拉与标签映射按数字取值，标签颜色遵循统一口径（启用/成功 `success`、停用/未知 `info`、进行中 `primary`、警告/已取消 `warning`、失败/危险 `danger`），环境标签颜色唯一维护在 `constants/tagStyle.ts`（AGENTS.md §4.5、§20.7）。

## 5. 已知边界与后续演进

- 登录为前端假实现，未接后端；`user` 表登录接口落地后替换 `api/user.ts` 底部注释部分；
- 菜单为静态路由，接入统一权限中心后由后端 routers JSON 动态渲染（模板已支持）；
- 鉴权中心与动态菜单的接入点、解耦要求和变更纪律见 AGENTS.md §21：登录/用户信息只经 `api/user.ts`、Token 只经 `utils/auth.ts`、菜单 JSON 类型以 `types/api.d.ts` 的 `RouteRecordItem` 为准，接入时只替换这三处实现，业务页面不改；
- 凭据与镜像仓库没有「测试连接」入口：凭据内容正确性、仓库地址可达性都要到实际拉取 / 推送时才暴露，后续可复用 SERVER_TEST 的思路加一类任务；
- 连通性测试日志抽屉只在服务器列表内提供；任务列表的日志查看仍是静态展示，未复用增量拉取，接发布模块时统一改为抽屉 + 增量拉取；
- 项目表单未提供三段 JSON 配置（build/runtime/health）编辑入口，待构建模块定义字段结构后以专用表单实现；
- 生产部署配置（Nginx 托管 + 反代）未编写，待 Docker 化交付阶段补齐；
- dashboard 首页仍为模板示例内容，待任务/发布模块落地后改造为平台概览。
